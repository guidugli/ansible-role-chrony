# Ansible Role: `chrony`

Installs and configures Chrony on supported Linux distributions. The role validates its public inputs, installs the native package, renders the packaging-specific configuration layout, and can manage the service when execution is not containerized.

## Requirements

- Ansible Core 2.17.x, as pinned by `requirements-dev.txt`.
- A target with a supported package manager and access to its configured repositories.
- Privilege supplied by the calling play when package, `/etc`, `/var`, or service changes require it.
- The `containers.podman` collection version 1.10.0 or newer for the included Molecule scenarios.

## Features

- Validated role inputs through `meta/argument_specs.yml` and cross-field assertions.
- Idempotent package installation and Jinja-based configuration rendering.
- Automatic detection of `conf.d` and `sources.d` layouts.
- Optional service management with container detection.
- Shared Molecule convergence and verification across the repository scenarios.

## Supported platforms

The generator-controlled metadata and Molecule inventory define Fedora, Ubuntu, and Debian coverage. Consult `meta/main.yml` and the scenario inventories for the exact versions generated by the repository tooling.

## Variables

At least one of `chrony_servers` or `chrony_pools` must contain an entry.

| Variable | Type | Default | Description |
| --- | --- | --- | --- |
| `chrony_debug` | boolean | `false` | Displays detected package and configuration layout details. |
| `chrony_manage_service` | boolean | `true` | Starts, enables, and restarts Chrony outside detected containers. |
| `chrony_servers` | list of strings | `[]` | Server directives without the leading `server` keyword. |
| `chrony_pools` | list of strings | `[]` | Pool directives without the leading `pool` keyword. |
| `chrony_sourcedir` | list of strings | `[]` | Additional directories containing Chrony source files. |
| `chrony_dhcp_sourcedir` | string | `/run/chrony-dhcp` | Directory containing DHCP-provided sources. |
| `chrony_driftfile` | string | `/var/lib/chrony/drift` | Frequency drift file path. |
| `chrony_makestep` | string | `1.0 3` | Clock-step threshold and update limit. |
| `chrony_maxupdateskew` | float | `100.0` | Maximum accepted update skew in parts per million. |
| `chrony_enable_rtcsync` | boolean | `true` | Enables periodic synchronization of the real-time clock. |
| `chrony_keyfile` | string | `{{ chrony_etc_path }}/chrony.keys` | Authentication key file path. |
| `chrony_ntsdumpdir` | string | `/var/lib/chrony` | Persistent Network Time Security data directory. |
| `chrony_leapsecmode` | string | `slew` | Leap-second mode: `system`, `step`, `slew`, or `ignore`. |
| `chrony_leapsectz` | string | `right/UTC` | Time zone database used for leap-second information. |
| `chrony_logdir` | string | `/var/log/chrony` | Chrony log directory. |
| `chrony_hwtimestamp` | string | `""` | Interface or wildcard for hardware timestamping; an empty value omits the directive. |
| `chrony_minsources` | integer | `0` | Required selectable sources; zero omits the directive instead of rendering an invalid value. |
| `chrony_allow` | list of strings | `[]` | Network prefixes allowed to query this NTP server. |
| `chrony_local` | string | `""` | Local-reference arguments; empty omits the directive. |
| `chrony_authselectmode` | string | `""` | Source authentication preference; empty omits the directive. |
| `chrony_log` | string | `""` | Space-separated log categories; empty omits the directive. |
| `chrony_generic_settings` | list of mappings | `[]` | Extra directives with `key`, optional `value`, and optional `minversion`. |

OS-specific package names, service names, paths, modes, and container types are internal variables in `vars/main.yml` and are not public role inputs.

## Example playbook

```yaml
---
- name: Configure time synchronization
  hosts: all
  become: true
  roles:
    - role: guidugli.chrony
      vars:
        chrony_pools:
          - pool.ntp.org iburst maxsources 4
        chrony_minsources: 1
```

## Molecule testing instructions

Create a virtual environment, install `requirements-dev.txt`, then run both repository scenarios:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
molecule test -s default
molecule test -s systemd
```

The shared converge play disables service management for ordinary containers. Verification checks package installation, configuration-file creation, and `chronyd -p` parsing without changing target state.

## Execution notes

The role never sets `become`, `become_user`, or `become_method`. Callers must use `become: true` when the connection user cannot install packages, write under `/etc` or `/var`, or manage services.

Container detection uses `ansible_facts['virtualization_type']`. In detected containers, service start, enable, and restart operations are skipped. Configuration and package tasks still run. The role uses the generic service module so the host service manager selects the appropriate backend. The protected `molecule/systemd` scenario remains the repository's systemd-oriented execution context.

## Release workflow

The protected release workflow is triggered by tags matching `v*`. Before tagging, run lint and both Molecule scenarios, then use the repository release automation under `scripts/`. Generator-controlled `meta/main.yml` must be refreshed through the existing generator rather than edited directly.
